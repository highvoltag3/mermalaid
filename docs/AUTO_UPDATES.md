# Auto-Updates for Mermalaid Desktop

Mermalaid desktop supports automatic in-app updates through the Tauri updater plugin. When a new version is published, users are notified and can update with a single click.

## How It Works

1. On startup (after a short delay), the app silently checks for updates
2. If a newer version exists, a non-intrusive banner appears with release info
3. Users can click "Update & Restart" to download and apply the update
4. Users can also click "Later" to skip that version (remembered until a newer version)
5. "Mermalaid > Check for Updates…" menu item provides manual checking with feedback

The updater only runs in the desktop app. The web version shows a simpler banner linking to the GitHub releases page.

## Setup (Maintainer Guide)

### 1. Generate a Signing Keypair

The updater requires a keypair to sign updates and verify authenticity.

```bash
# Generate keypair (saves private key to file, prints public key)
npm run tauri signer generate -- -w ~/.tauri/mermalaid.key
```

This creates:
- `~/.tauri/mermalaid.key` (private key, keep secret)
- `~/.tauri/mermalaid.key.pub` (public key)

The public key is printed to stdout and also saved to the `.pub` file.

### 2. Configure the Public Key

Open `src-tauri/tauri.conf.json` and replace the placeholder:

```json
{
  "plugins": {
    "updater": {
      "pubkey": "REPLACE_WITH_YOUR_PUBLIC_KEY",
      ...
    }
  }
}
```

Paste the public key (starts with `dW50...` or similar base64) in place of `REPLACE_WITH_YOUR_PUBLIC_KEY`.

### 3. Add GitHub Secrets

Add these secrets to your GitHub repository (Settings > Secrets and variables > Actions):

| Secret | Value |
|--------|-------|
| `TAURI_SIGNING_PRIVATE_KEY` | Contents of `~/.tauri/mermalaid.key` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Password you set when generating (can be empty) |

### 4. Verify the Configuration

After setting up:

1. Push a new version tag (e.g., `v1.10.0`)
2. Wait for the release workflow to complete
3. Check the draft release has:
   - `latest.json` file
   - `.sig` signature files for each platform
4. Publish the draft release

## Release Flow

```
1. Bump version in package.json and src-tauri/tauri.conf.json
2. Create and push a version tag: git tag v1.10.0 && git push origin v1.10.0
3. Wait for release.yml workflow to build all platforms
4. Review the DRAFT release on GitHub
5. Publish the release (click "Publish release" button)
6. Users on older versions will see the update banner
```

> **Note**: Only published releases are detected as updates. Draft releases are invisible to the updater. This lets you review artifacts before users see them.

## Update Endpoint

The updater fetches update info from:

```
https://github.com/highvoltag3/mermalaid/releases/latest/download/latest.json
```

This URL always points to the most recent published release's `latest.json` file.

### latest.json Format

Generated by tauri-action during the build:

```json
{
  "version": "1.10.0",
  "notes": "Release notes from GitHub...",
  "pub_date": "2025-01-15T12:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "base64-signature...",
      "url": "https://github.com/.../Mermalaid_1.10.0_aarch64.app.tar.gz"
    },
    "darwin-x86_64": {
      "signature": "base64-signature...",
      "url": "https://github.com/.../Mermalaid_1.10.0_x64.app.tar.gz"
    },
    "windows-x86_64": {
      "signature": "base64-signature...",
      "url": "https://github.com/.../Mermalaid_1.10.0_x64-setup.nsis.zip"
    }
  }
}
```

For universal macOS builds, both `darwin-aarch64` and `darwin-x86_64` point to the same universal binary.

## Platform Support

| Platform | Architecture | Update Format |
|----------|--------------|---------------|
| macOS | Universal (ARM64 + x86_64) | `.app.tar.gz` |
| Windows | x86_64 | NSIS `.exe` |

## Testing Updates

### Test Without Publishing

1. Build locally with signing key set:
   ```bash
   export TAURI_SIGNING_PRIVATE_KEY="your-private-key"
   npm run tauri:build
   ```

2. Check the build output for `.sig` files alongside installers

3. Manually inspect `latest.json` generation

### Test the Full Flow

1. Install an older version of the app
2. Publish a new release with higher version number
3. Launch the old app and wait for the update banner
4. Click "Update & Restart" and verify the app updates

## Troubleshooting

### "Auto-updates are not configured for this build"

The public key in `tauri.conf.json` is still the placeholder. Replace `REPLACE_WITH_YOUR_PUBLIC_KEY` with your actual public key.

### No update banner appears

- Check that the newer version is **published** (not draft)
- Verify `latest.json` exists in the release assets
- Check browser dev tools / console for network errors
- Ensure the public key matches the private key used for signing

### Signature verification failed

The private key used to sign the release doesn't match the public key in the app. Regenerate the keypair and update both the secret and config.

### Build warnings about missing signing key

If `TAURI_SIGNING_PRIVATE_KEY` is not set, the workflow logs a warning and skips updater artifact generation. The build still succeeds, but updates won't work until you add the secret.

## Security Considerations

- **Never commit the private key** to the repository
- The public key can be committed (it's in `tauri.conf.json`)
- Updates are cryptographically signed and verified before installation
- HTTPS ensures the update manifest can't be tampered with in transit
- Only GitHub Releases from the official repository are trusted
